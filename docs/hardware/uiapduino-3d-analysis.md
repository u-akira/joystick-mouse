## 1. モデル概要

- 解析日：2026-10-30（Asia/Tokyo）。
- Fusion MCP接続成功。開いている4文書のうち、アクティブな `UIAPduino_Pro_Micro` を対象とした。製品タイプは `adsk::fusion::Design`、ルート名は `(未保存)`。
- 解析開始・終了ともアクティブ文書は同一、`isSaved=false`、`isModified=true`。開始時点で未保存・変更あり。モデル変更、保存、Undo、Redo、文書切替は行っていない。

### 値の区分

| 記号 | 意味 |
|---|---|
| M | FusionのBRep形状からの実測値。実物の測定値ではない |
| D | Fusion Electronicsの設計データ、またはoccurrenceの配置データ |
| C | M/Dから計算した値。計算元の限界を引き継ぐ |
| U | 未確認・未検証。推定は確定寸法として使用しない |

以下、座標・長さ・寸法はすべて **mm**、回転角のみ **度**。小数桁数はAPI値の記録精度であり、製造精度・公差を保証しない。**電子部品の3D形状と実物寸法の一致は、登録済みモデルを含めて別途検証が必要。**

## 9. 解析に使用したFusion APIと取得方法

1. `fusion_mcp_read(queryType="document", operation="open")`：開始・終了時の文書一覧、アクティブ状態、保存・変更状態を照合。
2. `fusion_mcp_read(queryType="apiDocumentation", ...)`：allOccurrences、preciseBoundingBox、transform2、bRepBodies、BRepFace.geometry/loops/edges、Circle3D、Cylinder、Line3DのAPI説明を取得。
3. `fusion_mcp_execute(featureType="script", object={readOnly:true, script:...})`：Application.activeDocument/activeProduct、Design.rootComponent.allOccurrencesを読み取り。Occurrence.bRepBodiesの**ルートコンテキストのプロキシ**に対してBRepBody.preciseBoundingBoxを取得し、階層のローカル座標を誤って集計することを避けた。表示状態による除外はしていない。
4. 全ボディのmin/maxを統合してoccurrenceおよび全体のAABBを算出。サイズはmax−min。FRAME1除外は本報告での集計処理のみで、Fusionモデルから削除・非表示にしていない。
5. ボード本体のBRepEdge.geometryをCircle3D/Arc3Dとして読み、中心・半径を取得。BRepFace.geometryのCylinderで径1.70、Z=0～1.50の貫通形状を確認。上面Planeの外周BRepLoop.isOuterを選び、エッジの種類・頂点を列挙して矩形とキャスタレーションを確認。
6. `fusion_mcp_electronics_read`：Element、Hole、Board、Package3D、Wire（layer=20）を取得。Elementのvalue、angle、mirror、package3d_object_idを採用。すべてpagination.hasMore=falseで全件取得。BoardはFusionの一時出力先にあるUIAPduino_Pro_Micro v1.brdを返した。ローカルに置かれた.brd/.schを測定根拠の代替には使用していない。
7. **単位変換を分離**：Fusion Design APIのcm座標・半径は10倍、直径は半径の20倍。Electronics MCPはcoordinate_unit="mil"を返したため座標とHole.drillは0.0254倍。Hole.diameterはdrillと整合しない内部値を返したので不採用とし、drillとBRep円の直径を照合した。
8. 43要素のXY座標はElectronics換算値とoccurrence位置が0.00001以内で一致。取付穴3か所の中心・径も一致した。モデル測定値は小数点以下6桁まで丸めた。
9. executeは読み取り専用スクリプト3回のみ。プロパティsetter、モデル作成・変更・削除、executeTextCommand、保存、Undo、Redoは使用していない。

### 配置と外形取得の再現用スクリプト

以下は実際に使用した主要スクリプト。出力のtranslationとboxはmm。matrixはAPIの生データで平行移動成分がcmのため、本文の座標表には使用せずtranslationの変換値を採用した。

```python
import adsk.core, adsk.fusion, json
def p(v): return [round(v.x*10,6),round(v.y*10,6),round(v.z*10,6)]
def bb(b):
    q=b.preciseBoundingBox
    return [p(q.minPoint),p(q.maxPoint)]
def run(_context: str):
    a=adsk.core.Application.get()
    d=adsk.fusion.Design.cast(a.activeProduct)
    print(json.dumps({"document":a.activeDocument.name,"modified":a.activeDocument.isModified,"product":a.activeProduct.objectType,"root":d.rootComponent.name,"rootBodies":[{"name":b.name,"box":bb(b)} for b in d.rootComponent.bRepBodies],"occurrences":[{"path":o.fullPathName,"component":o.component.name,"partNumber":o.component.partNumber,"description":o.component.description,"translation":p(o.transform2.translation),"matrix":o.transform2.asArray(),"bodies":[{"name":b.name,"solid":b.isSolid,"box":bb(b)} for b in o.bRepBodies],"meshes":o.component.meshBodies.count} for o in d.rootComponent.allOccurrences]},ensure_ascii=False))
```

この結果の部品原点・包絡寸法を第5節に集計し、Electronicsの登録情報と照合した。寸法の取得成功は実物寸法の検証完了を意味しない。
